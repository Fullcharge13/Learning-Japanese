# 유키의 오사카 다코야키 가게 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 가나 평가 뒤 열리는, 카드 터치로 하루씩 운영하는 다코야키 가게 게임을 사나다 일본어에 넣는다.

**Architecture:** 데이터 표(`data/shop.js`) + 화면 없는 순수 규칙(`src/shop/rules.js`) + 그리기만 하는 화면(`src/ui/shop.js`). 저장은 기존 save 안의 `shop` 한 칸. 텃밭(리아와 파이썬)과 같은 짜임.

**Tech Stack:** 바닐라 JS(ES 모듈), node:test, Python(pytest·Pillow), Playwright Chromium(flow.py)

**Spec:** `docs/superpowers/specs/2026-11-09-다코야키-가게-설계.md`

## Global Constraints

- 저장 접두 `sanada-japanese.`, saveVer 그대로(2). `save.shop` 기본값: `{ v: 1, day: 0, money: 0, upgrades: [], stories: [], xpToday: { date: null, n: 0 }, run: null }`
- 화면 글자 한국어(해요체). 일본어 한자는 `字{よみ}` 표기, 화면에서 `ruby()`로. 로마자 없음
- 입력창 0개, 터치 44px 이상, 아이패드 700px 이상 1.3배(기존 CSS)
- 손님 수 6, plate2 +1, noren +1(최대 8). 팁 10%(neko 있으면 15%), 1円 아래 버림. 앱 XP +10, 날짜마다 2번까지
- 가게 열림: 1·2장 평가를 모두 통과
- 이야기 컷 일수: 1·2·3·4·5·7·9·11·13·15·18·21·24·27·30
- 그림: `src/img/shop/flow-01..15.png`, `story-01..15.png`, `guest-<id>.png`(15), 256px

## Review Focus

1. **장사 중에 레슨을 끝내거나 날짜가 바뀐 뒤 이어 하기** → 손님 목록이 바뀌면 안 된다. 하루를 시작할 때의 맥락(끝낸 장·메뉴·손님 수)을 `run`에 담아 둔다 → Task 2 `run keeps its customers when chapters change`
2. **정산 두 번 누르기·새로 고침 직후 정산** → 돈·일수·XP가 두 번 오르면 안 된다 → Task 2 `finishDay twice pays once`
3. **망가진 저장**(돈이 문자열·음수·거대값, 모르는 업그레이드 id, run.idx가 손님 수 넘음) → 기본값으로 정리, 앱이 멈추지 않는다 → Task 2 `cleanShop repairs broken shop`
4. **좋아하는 메뉴를 아직 안 가진 손님** → 가진 메뉴에서 주문한다 → Task 2 `guests only order owned menus`
5. **자정을 넘긴 장사** → XP 한도는 정산하는 날짜 기준 → Task 2 `xp cap counts the settle date`

- Produces (`src/shop/rules.js`):
  - `defaultShop() → Shop` / `cleanShop(raw) → Shop`
  - `doneChapter(examIds: {[ch]: lessonId}, completed: string[]) → number` — 평가를 통과한 장 가운데 가장 높은 번호(없으면 0)
  - `shopOpen(examIds, completed) → boolean` — 1·2장 평가 모두 통과
  - `ownedMenus(shop) → menuId[]`, `guestCount(shop) → number`
  - `startRun(shop, { date, doneCh }) → Shop` — `run = { date, dayNo: day+1, seed: date+":"+(day+1), ctx: { doneCh, menus, n }, idx: 0, step: "greet", results: [] }`. run이 이미 있으면 그대로
  - `dayCustomers(run) → [{ who, menu, count, tpl }]` — run.seed·run.ctx만 봄(문자열 시드 난수, 기존 `src/shuffle.js` 방식)
  - `orderLine(customer, doneCh) → { jp, hint: string|null }`
  - `greetCards(kind: "enter"|"leave", seed) → { cards: [{jp,ko}] ×3, answer: number }`
  - `judgeOrder(customer, menuId, count) → boolean`
  - `payFor(customer, allRight: boolean, shop) → number`
  - `recordStep(shop, ok: boolean, extra?: { menuId, count }) → Shop` — greet→order→bye→다음 손님, results에 `{ greet, order, bye, paid }`
  - `runDone(shop) → boolean`
  - `finishDay(save, today) → { save, report: { money, right, total, xp, story: storyId|null } } | Error` — run 없으면 Error. day+1, money+합계, stories에 그날 컷, XP(한도 안이면 earnXp + 퀘스트 tick "xp"), run=null
  - `buyUpgrade(shop, id) → Shop | Error`
