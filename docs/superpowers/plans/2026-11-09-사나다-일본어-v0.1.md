# 사나다 일본어 v0.1 — 작업 계획

- **Goal:** 해치와 한국어 v0.4를 복사해, 한국어 화자를 위한 카드식 일본어 입문 앱(가나 + NHK 1~12과 주제 단어, 선생님 사나다 유키)을 만든다.
- **Architecture:** 바탕 앱의 구조(정적 SPA, `localStorage` 저장, 장 파일 따로 받기, 서비스 작업자 오프라인)를 그대로 두고 데이터·글자·그림만 바꾼다. 새 모듈은 `src/ruby.js`(후리가나)와 `src/speak.js`(기기 음성) 둘뿐이다.
- **Tech Stack:** 바닐라 JS(ES 모듈), esbuild(빌드), Python 3(레슨 생성·빌드·시험), Playwright Chromium(화면 시험), node:test.
- **Spec:** `docs/superpowers/specs/2026-11-09-사나다-일본어-설계.md`
- **Global Constraints:**
  - 저장·오프라인 저장본 접두 `sanada-japanese.` (해치 `haechi-korean.`, 리아와 섞이지 않게)
  - 화면 글자 한국어(해요체), 일본어 한자는 `한자{읽기}` 표기로만 적고 화면에서 `<ruby>`로 그린다. 로마자 없음
  - 입력창 0개, 터치 대상 44px 이상, 아이패드 폭 700px 이상 1.3배
  - 단어 표·생성물 CC BY-SA 4.0, 코드 MIT. NHK 단어·대화·예문·제목을 옮기지 않는다
  - 하치마키 그림은 넣지 않는다
- **Review Focus:**
  1. 정답이 둘로 보이는 보기(같은 소리 あ/ア, お/を, 같은 뜻) → 작업 3 `test_no_twin_options`, 작업 9 `content.py`
  2. `ruby()` 이스케이프 누락(단어·이름에 `<` `&`) → 작업 2 `ruby escapes html`
  3. 해치 앱과 저장 섞임 → 작업 1 `keys.test.js`, 작업 9 `flow.py` 공존 시험
  4. 음성 없는 기기에서 오류 → 작업 2 `speak without speechSynthesis`
  5. 요음·촉음 카드 자르기(きょう, がっこう) → 작업 3 `test_kana_units`
- **실행 방식:** Native(이 세션이 모두 구현 → 마지막에 새 검토자 한 명이 브랜치 전체 검토). 작업 사이 의존이 커서(글자 번역이 여러 파일에 걸침) 작업마다 따로 맡기는 이득이 작다.

## 작업 2. `ruby.js`·`speak.js`

**Files:** `src/ruby.js`, `src/speak.js`, `tests/unit/ruby.test.js`, `tests/unit/speak.test.js`
**Produces:**
```js
ruby(text: string): string   // esc + 한자{읽기} → <ruby>한자<rt>읽기</rt></ruby>
kana(text: string): string   // 한자{읽기} → 읽기
plain(text: string): string  // {읽기} 지움
canSpeak(win = globalThis): boolean
speak(text: string, win = globalThis): boolean  // kana(text)를 ja-JP로, 실패 시 false(던지지 않음)
```
- [ ] Test `ruby`: `"学生{がくせい}です"` → `<ruby>学生<rt>がくせい</rt></ruby>です`; `"行{い}きます"` → `<ruby>行<rt>い</rt></ruby>きます`; `"<b>&"` → `&lt;b&gt;&amp;`; `"a{<x>}"`의 읽기도 이스케이프; 짝 없는 `{`는 글자 그대로
- [ ] Test `kana`·`plain`: 위 예의 `がくせいです`·`学生です`
- [ ] Test `speak`: 가짜 win에 cancel→speak 순서, utterance.lang `ja-JP`, text 읽기; `speechSynthesis` 없으면 `canSpeak()` false·`speak()` false; speak가 던지면 false
