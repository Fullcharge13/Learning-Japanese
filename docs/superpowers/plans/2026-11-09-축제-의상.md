# 보관함 축제 의상 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 보관함의 일본 물건 34개를 유키가 입은 지역 축제 의상 15벌로 바꾸고, 옛 물건 값은 엔으로 돌려준다.

**Architecture:** 저장의 `items`/`item` 칸과 `ITEMS` 표 모양은 그대로 두고 내용만 의상으로 바꾼다(방식 A). 옛 물건 처리는 `migrate` 한 곳에서 해서 앱 시작·가져오기·개발자 모드 칸이 모두 같은 길을 지난다. `yukiImg`가 의상이면 의상 그림을 내보내 부르는 화면은 고치지 않는다.

**Tech Stack:** 바닐라 JS ES 모듈, node:test, Python(Pillow, pytest, Playwright), esbuild 빌드(build.py).

**Spec:** `docs/superpowers/specs/2026-11-09-축제-의상-설계.md`

## Global Constraints

- 의상 15벌의 id·ko·jp·price는 설계서 §2 표 그대로. 첫 칸 `{ id: "none", ko: "평소 옷", jp: "いつもの服{ふく}", price: null, unlock: "start" }`.
- 가격 분포 120×3, 180×4, 240×4, 300×3. `nebuta`는 `price: null, unlock: "streak30"`.
- 새 id는 옛 물건 id와 겹치지 않는다.
- 그림: `src/img/outfits/<id>.png`, 256×256, 크림색 배경 투명. `src/img/items/`는 지운다.
- 안내 문구: 「보관함이 축제 의상으로 바뀌었어요. 가지고 있던 물건 값 N엔을 돌려드렸어요.」
- 「물건」이라는 사용자 문구는 보관함·배지·대사에서 「의상」으로.
- 한글 표기는 국립국어원 표기법(마쓰리·덴진·얏사).

## Review Focus

1. 같은 옛 저장을 다시 불러오거나 새로 고침 → 엔은 한 번만 돌아온다 (Task 3 `refund once`).
2. 옛 저장 파일 가져오기 → 그 저장도 돌려받고 안내가 바로 뜬다 (Task 3 migrate 시험 + Task 4 가져오기 경로 `takeRefund`).
3. 개발자 모드 칸에 옛 물건이 있을 때 → 같은 처리 (Task 3 `dev slot refunds too`).
4. 저장의 `item_refund`가 깨진 값(문자열·음수·소수) → 무시하고 안내 없음 (Task 3 `bad item_refund`).
5. 오프라인 → 의상 그림도 미리 받아 둔다 (Task 1 build 시험: sw 목록에 outfits 15장, items 없음).
