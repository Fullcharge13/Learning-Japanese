# JLPT N5 채우기 설계 (문법 4·5 · 독해 · 청해)

> 날짜: 2026-11-10 · 상태: 사용자 승인(설계 1/2·2/2 「ㄱㄱ」), 문서 검토 대기
> 앞 설계: `2026-11-09-n5-완성-설계.md`. N4·N3은 이 작업 뒤 각자 설계(장 201번·301번부터).

## 1. 목적
N5 검토 결과 단어(664/664)·한자(79/79)는 완성이지만 문법은 약 60%(18항목), 독해·청해는 모의고사 맛보기뿐이다. N4로 가기 전에 N5 시험 영역을 모두 앱 안에서 연습할 수 있게 채운다.

성공 기준
- N5 길 = 단어 1~14장 → 문법 15~17장 → 한자 18~19장 → 문법 20~21장 → 독해 22장 → 청해 23장 → 모의고사 24장. 끝까지 풀 수 있다.
- 문법 30항목(18 + 새 12), 독해 12편, 청해 20문제.
- 모의고사를 이미 푼 사람의 기록이 새 번호(24장)로 옮겨지고, 문법 4를 푼 것처럼 보이지 않는다.

- 문법 4·5는 지금 문법과 같은 원본(`data/jlpt-n5-grammar.json`에 항목 추가, `chapter` 120·121)과 같은 생성기·문제 꼴(설명 카드 + 빈칸 + 문장 만들기 + `accept` 다른 순서 + 장 평가). 보통형(사전형·た형)은 따로 항목을 두지 않고 〜たり·〜とき·〜ほうがいい 등 항목 안에서 형태를 함께 설명.
- 모의고사 문법 칸 후보에 문법 4·5 문제가 자동으로 들어간다(앞 장 101~123에서 고름). 독해·청해 칸은 지금처럼 `data/jlpt-n5-mock.json`.
- N5 완주: JLPT 길 마지막 레슨(`124-3`)을 처음 끝냈을 때(규칙 그대로).

## 3. 저장 옮기기 (120 → 124)
- `SAVE_VER` 2 → 3. `migrate()`에서 옛 판(< 3)이면 레슨 id `120-n` → `124-n`: `completed_lessons`, `grading_results`의 키, `submission_logs`의 레슨 id, `seen_updates`의 키.
- 하던 레슨 기록(`resume.js`, 저장과 다른 칸): 옛 판에서 올라온 첫 실행에 레슨 id가 `120-`이면 같은 규칙으로 옮긴다.
- 개발자 모드 저장도 같은 `migrate()`를 거친다.
- 새 판(3)은 다시 옮기지 않는다(문법 4의 `120-n`을 지키려고).

## 4. 독해 (122장)
원본 `data/jlpt-n5-reading.json`: 글마다 `{id: "r5-01", lesson: 1~4, text, ko, questions: [{q, options(4), answer 0}]}`.

| 레슨 | 글 | 수 |
|---|---|---|
| 독해 1 | 메모·메시지 | 3편 × 2문제 |
| 독해 2 | 일기·짧은 글 | 3편 × 2문제 |
| 독해 3 | 조금 긴 글(200자 정도) | 3편 × 2문제 |
| 독해 4 | 안내문·시간표 정보 찾기 | 3편 × 2문제 |

- 문제 꼴: 지금 모의고사 독해(`kind: "reading"`, 문장 칸에 글, 🔊, 답한 뒤 `explain`에 한국어 번역). 질문·보기는 일본어(후리가나).
- 레슨 카드: 글 종류 설명 한 장(예 「메모는 누가 누구에게, 무엇을 부탁하는지 먼저 찾아요」).
- 개념 id `r5-01`~`r5-12`, 이름표 「독해 · <제목>」.

## 5. 청해 (123장)
원본 `data/jlpt-n5-listening.json`: 문제마다 `{id: "l5-01", lesson: 1~4, say, q, options, answer 0, ko}`.

| 레슨 | 꼴 | 듣는 것 `say` | 질문 `q` | 보기 |
|---|---|---|---|---|
| 청해 1 | 과제 이해 | 대화 2~4줄 | 한국어(「남자는 이다음에 무엇을 해요?」) | 한국어 4개 |
| 청해 2 | 포인트 이해 | 대화 2~4줄 | 한국어(「여자는 왜 늦었어요?」) | 한국어 4개 |
| 청해 3 | 발화 표현 | 없음(상황은 질문) | 한국어 상황(「친구에게 펜을 빌리고 싶어요. 뭐라고 말해요?」) | 일본어 3개 |
| 청해 4 | 즉시 응답 | 한 마디 | 「잘 듣고 알맞은 대답을 골라요」 | 일본어 3개 |

- 레슨마다 5문제(20문제). 청해 3은 듣는 것이 없으므로 `kind: "listen"`이 아닌 일반 choice(`kind: "speech"`).
- 대화 표기: `say`에 줄바꿈으로 줄을 나누고 줄 앞에 `男：`/`女：`. 
- 개념 id `l5-01`~`l5-20`, 이름표 「청해 · n」.

## 6. 화면·소리
- `speak(text)`: 줄바꿈이 있으면 줄마다 따로 읽는다(처음 한 번만 `cancel`). 줄 앞 `男：`은 낮게(pitch 0.8), `女：`은 높게(pitch 1.25), 표시는 소리로 읽지 않는다. 줄바꿈이 없으면 지금과 같다.
- `listenBox`: 「글자로 보기」 안의 대화를 「남: … / 여: …」 줄로(한 줄씩 `<p>`). 음성이 없는 기기는 처음부터 같은 줄 글자.
- 설정 JLPT 목록은 장 24개(앞 3장 + 더보기 그대로). JLPT 화면 끝 문구 「N5 · 24장 모의고사까지 있어요…」.

## 7. 시험
- 단위(node): `speak` 줄 나누기·높낮이·표시 안 읽기(가짜 음성), `listenBox` 대화 줄, 저장 옮기기(옛 판 120-n → 124-n, 새 판은 그대로), resume 옮기기.
- 데이터(pytest·content.py): 문법 30항목(id g5-01~30), 새 항목 규칙은 지금 문법과 같음 / 독해 12편 × 2문제, 보기 4개 서로 다름, 후리가나 / 청해 20문제, 대화 2~4줄·줄마다 男/女, 청해 1·2·4 질문에 일본어 없음, 청해 3·4 보기 3개 / 장 120~124 생성, 모의고사 회당 25문제.
- 화면(flow): 대화 듣기 문제(🔊, 「글자로 보기」에 남·여 줄), 옛 저장(모의고사 끝냄)으로 열면 24장이 끝남·20장은 안 끝남.
- 시뮬레이션: N5 길 1~24장 전부.

## 8. 하지 않는 것
그림 보고 고르는 청해, 고품질 음성, 합격선 표시, N4·N3(다음 설계).
